# SEARPC participation control protocol-closure specification

## Frozen scope

This specification defines the RQ4 evidence-to-participation control boundary and its reporting. Message evidence, role authorization, domain aggregation, and the fixed-quorum process measurements use their registered evaluation configurations.

The data-role state remains an application-facing provider-action authorization. No new data-state gate is inserted into event fusion, `RC_e`, or the fast path.

## Authority sinks and capabilities

Runtime authority is sink-oriented. Control functions accept typed capabilities, not raw roots.

| Capability | Authorized sink | Excluded inputs |
|---|---|---|
| `SelectionCapability` | `COMMITTEE_SEED` | risk score/level, event digest, view, external event label |
| `AuditCapability(core)` | `CORE_AUDIT_PLAN` | all content-risk fields |
| `AuditCapability(extension)` | `EXTENSION_AUDIT_PLAN` | validator failure/FSM and finality state |
| `RiskCapability` | `EVENT_RISK`, `EXTENSION_GAMMA`, `EXTENSION_AUDIT_PLAN` | committee seed and core audit plan |

For `d=f(e_1,...,e_n)`, `authority(d)` is the safe meet of input authorities. Hashing, serialization, Merkle commitment, or wrapping never adds a sink.

## Replay-safe canonical evidence

Audit responses are bound to an issuer namespace keyed by evidence kind, subject, source domain, source height, and schema. A stateful `CanonicalEvidenceLog` is retained across heights:

- a first valid response is committed once;
- an identical response to the same challenge is idempotent;
- a different envelope ID cannot create a second challenge;
- a conflicting response to an already committed challenge is rejected;
- independent audit domains remain distinct challenges;
- late records enter only a later eligible cut.

The rolling audit root commits replay-stable canonical payloads rather than caller-selected envelope IDs.

## Complete registry commitment

`registry_root` commits the canonical, validator-ID-sorted list of:

`{validator_id, credential_digest, correlation_domain, eligibility, registry_epoch, configuration_digest}`.

Changing any committed field changes the root. Duplicate validator IDs and empty registries are rejected.

## Commit-before-reveal selection

For the randomness value `B_h` used at height `h`, the required ordering is:

`Commit(R_seed(h)) < Reveal(B_h)`.

Then:

`sigma_h^p = H(B_h, R_seed(h), p)`, where `p` is `primary`, `resample`, or `reputation-top`.

Production `B_h` should be generated by an unbiasable threshold signature, VRF, or distributed randomness beacon. The experiments use a deterministic frozen substitute for paired replay and make no unpredictability claim.

The SEARPC-owned selector exposes no `event_id` parameter. The lower generic selector receives a fixed internal domain-separation label; height and purpose variation is already committed in the typed seed capability.

## Audit-plan commitments

`Proj_audit,core` and `Proj_audit,ext` are input commitments. The planner consumes the corresponding capability and emits `R_audit,out`, committing the authorized input projection, sorted targets, and coverage. Thus the recorded audit-plan root is bound to the executed target set.
