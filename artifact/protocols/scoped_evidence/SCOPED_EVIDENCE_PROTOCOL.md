# SEARPC scoped-evidence evaluation protocol

This specification defines the evidence boundary, authorization rules, and paired evaluation parameters.

## 1. Numerical protocol

The evaluation uses `k=13`, `q_k=9`, final `Q=27` for `N=40` (`Q=11` for `N=16` harness), `kappa=0.40`, role threshold `tau=0.50`, 5%/95% Beta-form bounds, vehicle 3-failure/10-success lock, or validator 3-failure plus 5-success Q→P / 5-success P→A recovery with at least two audit domains.

## 2. Canonical evidence boundary

Local application evidence and replicated protocol evidence are separated. A vehicle-side application may consume locally delivered authenticated evidence. Any evidence that changes validator admission or committee construction must be included in the canonical evidence cut visible before the height-`h` decision cut. The committee seed binds `(height, view, evidence_state_root, purpose)`. Evidence arriving after the cut affects only later heights.

Replica-determinism claim: equal canonical evidence-state root, domain map, base seed, height and view imply the same admission projection and committee selection.

## 3. Executable three-state authorization

For opinion provider `j`, the frozen scoped evidence fusion authority is

`w_tilde(j,e) = 1[State(j,o) != malicious] * LCB(j,o) * rho(e)`.

No new threshold is introduced. `uncertain` and `trusted` keep their continuous LCB weights; only a failure-locked/UCB-malicious state has zero high-authority fusion weight. A malicious data-provider state denies high-authority service but does not prevent the message from being inspected, logged or adjudicated.

## 4. Validator state representation

Data/opinion roles use Beta-form weighted pseudo-count evidence. Validator online admission is the delivered-audit Active/Quarantine/Probation finite-state controller. Any long-horizon validator Beta state is telemetry/diagnostic only and does not write main-path admission, committee, hint or finality state.

## 5. Typed write authority

The executable type/write-permission matrix is implemented in `artifact/code/participation_control/typed_authority.py`. Hidden fault labels have no online write authority. SEARPC may write event-risk, role-state, validator-admission, audit-policy and participation/hint metadata only; it cannot write base-BFT quorum, lock, view-change or final commit state.

## 6. Robustness experiments

- RQ2/RQ3 affected-result rerun: same 20 frozen seeds and grids.
- Transcript robustness: legal-sign, withholding, selective-sign, invalid/equivocation, and honest-network-timeout; same committees/fault labels/audit histories.
- Audit-budget attribution: shared exogenous 7 audits/block; equal total budget 7 audits/block with policy-specific targeting; full adaptive audit policy. Seven is fixed as `ceil(0.5*k)` before outcomes.
- Vehicle adjudication sensitivity: error `{0,5,10%}` × canonical delay `{0,10,30}` on the first five frozen paired seeds; role test at 50% overlap, domain test at concentrated `n=7`.
- RQ5 extension: same custom fixed-Q harness, 5 launches × 500 measured blocks/cell, exact runtime/hardware snapshot. WAN/netem is optional and, if unavailable, is not silently simulated.
- Calibrated-RF backend swap is prespecified, but may only be run from the exact holdout feature tensor/raw archive and the already-defined training/calibration protocol. RF probabilities must be generated by the specified RF model.

## 7. Stop rules

No outcome-driven threshold changes, no replacement of negative results, and no new baseline selected because it makes SEARPC look better. A later method change requires a new version and rerun of all affected dependent results.
